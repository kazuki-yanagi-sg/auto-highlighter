本文レンダリングが稀に崩れる(snake_case を数式と誤検出)iter 1/5

🕒 2026-06-18T07:30:00 · 📄 frontend/src/math.tsx (renderPlain / matchDelim)

エラー出力

KaTeX 警告: "Unicode text character "で" used in math mode [unicodeTextInMathMode]"
再現入力(実記事セグメント):
  "スコープはread_qiitaとwrite_qiitaを選択"
  "コアテーブル: horses, race_entries, race_results"
  "価格は $5 で、別の $10 もある。"
→ read_qiita / race_entries / $...$ 内の日本語が KaTeX math mode で描画され表示が崩れる。

原因解析

renderPlain の数式判定が MATH_SIGNAL = /[\\^_]/ で、区切りの無い地の文でも _・^ を含む非日本語塊を数式とみなしていた。技術記事の snake_case 識別子 (read_qiita 等)に誤ヒットし KaTeX 描画 → 崩れ。記事ごとに有無が変わるため「たまに」発生。 加えて matchDelim が地の文中の単独 $ を区切りと誤認し、間の日本語を数式に飲み込んでいた。

適用した修正

1) MATH_SIGNAL を /\\/ に厳格化(バックスラッシュ=LaTeXコマンドがある時だけ数式)。
   _ / ^ 単独では数式化しない → snake_case・添字記法・パスを誤描画しない。
2) matchDelim: 区切りの中身に日本語(JP)を含む場合は数式扱いしない($ 誤検出を防止)。
3) renderSegmentHtml を try/catch で包み、想定外入力でも素テキストに退避(本文全体を巻き込まない)。
   回帰テスト: src/tests/render_robustness.test.ts(実記事セグメント+意地悪入力で検証)。

結果

npm test → 55 passed / tsc --noEmit OK。\eta・$E=mc^2$ の正規数式は従来どおり描画、snake_case は地の文として表示。

PDFの行列が大きな余白で分断され表示が壊れるiter 1/5

🕒 2026-06-18T07:55:00 · 📄 backend/app/services/pdf.py (_paragraphs) + frontend/src/components/HighlightedText.tsx

エラー出力

スクリーンショット: 式(6.3)の行列が
  f : g → gl2(R) : aA + bX →
  b a            ← 余白
  0 −a           ← 余白
  (6.3)
と各行が大きな段落余白で分断され、壊れて見える。

原因解析

PDFのテキスト層には行列・分数の2次元配置情報が無く、pdfminer は各行をバラして抽出する。 旧 _paragraphs は数式行を1行ずつ別ブロックにしていたため、各行が別 .para となり 段落余白(0.9em)で分断 → 壊れて見えた。

適用した修正

1) pdf.py _paragraphs: 日本語を含まない行(短い or 数式記号を含む)を「数式行」とみなし、
   連続するものを改行付きで1ブロックにまとめる(行列が1つの固まりになる)。英文地の文は誤巻込しない。
2) HighlightedText: 日本語を含まない文を seg-display(block表示)にして1行ずつ縦に詰めて並べる。
   同 block は1つの .para にまとまるため、行間は詰まり段落余白で分断されない。
備考: PDFからの行列・分数の2次元完全復元は原理的に不可(要 数式OCR)。本対応は崩れ表示の解消まで。

結果

再POST後、行列ブロックが1段落に縦並びでまとまることを API とスクリーンショットで確認。 backend 121 passed / frontend 55 passed。

原因解析

PDF の読み取り順は、ページ下部の脚注・ノンブル・ページ上部のランニングヘッダといった 「ページ付帯物」を本文に混ぜ込む。これらが段落として本文中に出現し読みを阻害していた。 本文の脚注マーカー(例 "リー代数*1" = 後ろが日本語)と、脚注定義("*1 Lie algebra" = 後ろが英語) は形が異なる点を利用して区別できる。

適用した修正

pdf.py:
  1) 脚注定義 /\*\d+\s+[A-Za-z].../ を各行から除去(本文の "リー代数*1" は後ろが日本語なので残る)。
  2) ノンブル(^\d{1,4}$ のみの行)を破棄。
  3) ランニングヘッダ(第N章/ N.N で始まる短い見出し)の繰り返しは最初の1回だけ残しdedup。
     "証明." 等の繰り返し本文は dedup 対象外(見出しパターンに限定)。
回帰テスト: test_pdf.py に脚注/ノンブル/ヘッダdedup の各ケースを追加。

結果

実PDF再抽出でノイズ0(ブロック126→96)。スクリーンショットで 6.2 節がクリーン表示なのを確認。 backend 125 passed。

行列が2次元で描画されない(縦割りのまま)iter 1/5

🕒 2026-06-18T09:30:00 · 📄 backend/app/services/pdf.py (座標再構成)

エラー出力

式(6.3)の行列が b / a / 0 −a と縦割りのまま。本来は ( a b ; 0 −a ) の2x2行列。
ユーザー選択: 座標解析で自前再構成。

原因解析

テキスト抽出(extract_text)は2次元配置を1次元化するため行列が縦に割れる。 pdfminer のレイアウト座標(x,y)を使えば、行=y・列=x でグリッドを復元できる。

適用した修正

pdf.py を extract_pages(座標つき)ベースに変更:
  1) セル候補(短い・日本語/関係記号なし・本文余白内)を union-find で近接クラスタ化。
  2) 行=y, 列=x でグリッド化。各行のセル数が揃う2列以上のみ pmatrix 化(不整合は不採用=誤検出回避)。
  3) $$\begin{pmatrix}..\end{pmatrix}$$ に置換 → フロントの既存KaTeXが2次元描画。
  4) 読み順は視覚行(yが近い断片)でまとめ左→右に整列(リード→行列→式番号)。
回帰テスト: test_matrix_reconstructed_from_coordinates / test_inconsistent_rows_not_treated_as_matrix。

結果

実PDFで (6.3)→pmatrix[a,b;0,-a], (6.9)→2行列 を再構成。KaTeXで2x2行列として描画されるのを スクリーンショットで確認。backend 127 passed / frontend 56 passed。
