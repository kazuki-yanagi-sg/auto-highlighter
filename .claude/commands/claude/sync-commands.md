# カスタムコマンド同期

別のプロジェクトのcustom commandと比較し、新しく追加されたコマンドや更新されたコマンドを現在のプロジェクトに同期します。

## 引数の処理

引数: $ARGUMENTS

- 引数指定時: 指定されたパスのプロジェクトと比較
- 引数未指定時: ユーザーにプロジェクトパスを質問

## 公式仕様（Claude Code Documentation準拠）

### カスタムコマンドのファイル構造

**配置場所:**
- プロジェクトコマンド: `.claude/commands/`
- パーソナルコマンド: `~/.claude/commands/`

**サブディレクトリ:**
- サブディレクトリは組織目的のみ（コマンド名には影響しない）
- 例: `.claude/commands/frontend/component.md` → `/component` コマンド

### フロントマターフィールド（公式）

| フィールド | 目的 | デフォルト |
|-----------|------|----------|
| `allowed-tools` | 使用可能なツールのリスト | 会話から継承 |
| `argument-hint` | 引数のヒント（自動補完で表示） | なし |
| `description` | コマンドの説明 | プロンプトの最初の行 |
| `model` | 特定のモデルを指定 | 会話から継承 |
| `disable-model-invocation` | 自動実行を防止 | false |

## 実行フロー

1. **ソースプロジェクトの確認**
   - 引数で指定されたパスの存在確認
   - `.claude/commands/`ディレクトリの存在確認

2. **コマンド一覧の取得**
   - ソースプロジェクトの全コマンドファイルを取得（`.claude/commands/**/*.md`）
   - 現在のプロジェクトの全コマンドファイルを取得

3. **差分分析**
   - 新規コマンドの検出（ソースにあって現在のプロジェクトにないもの）
   - 更新コマンドの検出（両方に存在し、内容に差分があるもの）
   - 比較基準: ファイル内容のdiff

4. **同期対象のプレビュー**
   - 新規追加されるコマンド一覧を表示
   - 更新されるコマンド一覧を表示（diffも表示）
   - ユーザーに確認を求める

5. **同期実行**
   - 新規コマンドファイルをコピー
   - 更新コマンドファイルを上書き

6. **プロジェクト固有ファイルのメンテナンス（必須）**
   - コマンド同期後、以下のファイルを必ず更新すること:
     - `.claude/commands/registry.json`: 新規コマンドの登録、`statistics.total_commands`の更新
     - `.claude/docs/COMMANDS.md`: コマンド一覧テーブルへの追加、総コマンド数の更新
     - `.claude/lib/common.md`: 共通仕様に変更があれば同期（diffで確認）

7. **同期結果の報告**
   - 追加されたコマンド数
   - 更新されたコマンド数
   - スキップされたコマンド（あれば理由も）

## 同期ルール

### 新規コマンド
- ソースプロジェクトにあり、現在のプロジェクトにないコマンド
- サブディレクトリ構造を維持してコピー

### 更新コマンド
- 両方に存在するコマンド
- ファイル内容に差分がある場合はソースを採用

### 除外対象
- 現在のプロジェクト固有のコマンド（ソースにないもの）は削除しない

## 使用方法

- `/claude:sync-commands "/path/to/source/project"` - 指定プロジェクトから同期
- `/claude:sync-commands` - プロジェクトパスを対話的に入力

## 注意事項

- 同期前に必ず現在のブランチの状態を確認
- 同期は上書きなので、ローカルの変更がある場合は先にcommitを推奨
- プロジェクト固有のカスタマイズが必要な場合は同期後に手動調整
