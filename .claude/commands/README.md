# カスタムコマンド書き方規約

## 基本構造

すべてのカスタムコマンドは以下の構成で記述する：

```markdown
---
allowed-tools: [ツール名の配列]
description: 1行で簡潔な説明（日本語）
---

# コマンド名（日本語）

コマンドの概要説明（1行）。

## 引数の処理

引数: $ARGUMENTS

- 引数指定時: どのように処理するか
- 引数未指定時: どのように処理するか

## 実行フロー

1. **ステップ名**: 説明
2. **ステップ名**: 説明
3. **ステップ名**: 説明

## 使用方法

- `/category:action` - 基本的な使い方
- `/category:action "引数"` - 引数付きの使い方

## カスタムコマンド共通仕様

@.claude/lib/common.md
```

## フロントマター規約

### allowed-tools

- 使用するツールを最小限に限定
- 配列形式で記述: `[Tool1, Tool2, Tool3]`
- ワイルドカード使用可: `mcp__github__*`

### description

- 日本語で1行で簡潔に記述
- 「〜する」「〜を実行」で終わる動詞形
- 50文字以内を目安

## セクション規約

### 1. タイトル（H1）

- コマンドの機能を表す日本語名称
- 「〜」で体言止め
- 例: `E2Eテスト`、`安全なリファクタリング`

### 2. 概要説明

- タイトル直後に1行で説明
- 「〜します。」で終わる
- 技術的詳細は含めない

### 3. 引数の処理（H2）

- 必須セクション
- `引数: $ARGUMENTS` を必ず記載
- 引数の有無による動作の違いを箇条書き
- 「引数指定時:」「引数未指定時:」の形式

### 4. 実行フロー（H2）

- 必須セクション
- 番号付きリストで記述
- 各ステップは **太字** でステップ名を記載
- ステップ名の後にコロンと説明
- 3〜7ステップを目安

### 5. 使用方法（H2）

- 必須セクション
- 実際のコマンド例を記載
- 基本形と引数付きの例を含める
- コードブロックは使わず、箇条書きで記述

### 6. カスタムコマンド共通仕様（H2）

- 必須セクション
- 全てのコマンドファイルの末尾に記載
- `## カスタムコマンド共通仕様` の見出しの後に `@.claude/lib/common.md` を記載
- この参照により、全コマンド共通のルール（統計ファイルの自動ステージング等）が適用される

## オプショナルセクション

必要に応じて以下のセクションを追加可能：

### チーム・プロジェクト情報（H2）

- プロジェクト固有の情報が必要な場合
- IDや固定値を記載

### 注意事項

- ⚠️ アイコンで重要な注意を強調
- **太字** で強調

## スタイルガイドライン

### 文体

- 敬語は使わない（「します」「実行」等の丁寧語は可）
- 簡潔で明確な表現
- 技術用語は正確に使用

### フォーマット

- リスト項目は `-` で統一
- 番号付きリストは `1.` 形式
- コマンド例は `` ` `` で囲む
- ファイルパスは `` ` `` で囲む

### 禁止事項

- 冗長な説明
- 実装の詳細記述
- 不必要なコードブロック
- 英語のみの説明

## コマンド例の記載方法

```markdown
## 使用方法

- `/dev:refactor-safe` - 仕様を壊さない安全なリファクタリング
- `/dev:refactor-safe "login"` - 対象を指定したリファクタリング
```

## 更新時の注意

1. registry.jsonの同時更新
2. 既存コマンドとの整合性確認
3. カテゴリ分類の適切性確認
