# お客さん向け手順書作成スキル

お客さん向けの操作手順書をHTMLファイルとして作成するスキル。

## 概要

**ユーザーとの認識合わせを最優先**とし、以下のフローで進める:
1. シナリオの認識合わせ（ユーザー承認必須）
2. HTML下書き作成
3. データ構成確認
4. 画面キャプチャ撮影
5. 完成・確認

---

## フェーズ1: シナリオの認識合わせ（ユーザー承認必須）

### ステップ1-1: 画面構成の調査

シナリオ提示前に、関連する画面を調査する。

**調査方法:**
1. `client/messages/metadata/ja.json`で画面URL・画面名を確認
2. 必要に応じてExploreエージェントで画面構成を調査
3. 各画面でどんな操作ができるかを把握

### ステップ1-2: シナリオを表形式で提示

調査結果をもとに、**表形式**でシナリオを提示する:

```markdown
| Step | 画面名 | 操作内容 | 備考 |
|------|--------|----------|------|
| 1 | ログイン画面 | メールアドレス・パスワード入力してログイン | |
| 2 | 在庫一覧画面 | 荷主コード209で検索して在庫確認 | 出庫前の状態確認 |
| 3 | 出庫実績登録画面 | ファイルアップロードでCSV取込 | 要CSVファイル |
| ... | ... | ... | ... |
```

### ステップ1-3: ユーザー承認を得る

- ユーザーから「OK」等の承認コメントを得るまでシナリオを改善し続ける
- 不明点があれば質問して明確にする
- **承認なしで次のフェーズに進んではいけない**

## フェーズ2: HTML下書き作成

### ステップ2-1: 出力ディレクトリ作成

```bash
mkdir -p .tmp/how-to/{荷主コード}_{シナリオ名}/images/
mkdir -p .tmp/how-to/{荷主コード}_{シナリオ名}/outputs/
```

**ディレクトリ用途:**
- `images/` → スクリーンショット画像
- `outputs/` → 手順書で使用するサンプルファイル（CSV等）

### ステップ2-2: HTML構造の作成

承認されたシナリオをもとに、**キャプチャなし**でHTMLの構造を作成:
- 各ステップのタイトル・説明文
- 操作手順のリスト
- 画像のプレースホルダー（`./images/XX-画面名.png`）

テンプレート: `.claude/skills/create-customer-howto/templates/howto-template.html`

**置換変数:**
- `{{SCENARIO_TITLE}}` → シナリオタイトル
- `{{SCENARIO_OVERVIEW}}` → 業務シナリオ概要（この手順書で何ができるか）
- `{{SIDEBAR_ITEMS}}` → サイドバー項目
- `{{STEPS}}` → ステップカード
- `{{TOTAL_STEPS}}` → 総ステップ数

**業務シナリオ概要の書き方:**
手順の0番目として、この手順書で達成できる業務目的を**箇条書きで簡潔に**記載する。

```html
<div class="step-details">
    <h4>やりたいこと</h4>
    <ul style="list-style: disc; margin-left: 1.5rem;">
        <li>【目的1を簡潔に】</li>
        <li>【目的2を簡潔に】</li>
    </ul>
</div>
<div class="step-details">
    <h4>業務フロー</h4>
    <ol>
        <li>【ステップ1】</li>
        <li>【ステップ2】</li>
        <li>...</li>
    </ol>
</div>
<div class="tip-box">
    <h5>ポイント</h5>
    <ul style="list-style: disc; margin-left: 1rem; margin-top: 0.5rem;">
        <li>【注意点1】</li>
        <li>【注意点2】</li>
    </ul>
</div>
```

**書き方のルール:**
- 長文禁止 → 箇条書きで要点のみ
- 1項目1行で収まる長さに

## フェーズ3: データ構成確認

### ステップ3-1: DB接続情報の取得

```bash
cat api/.env | grep -E "POSTGRES_USER|POSTGRES_DB|POSTGRES_PORT"
```

**重要**: ポート番号は`.env`から取得すること（ハードコード禁止）

### ステップ3-2: 荷主データの確認

```bash
docker compose exec -T db psql -U $POSTGRES_USER -d $POSTGRES_DB -p $POSTGRES_PORT -c "
SELECT id, name, system_code FROM consignors WHERE system_code = {荷主コード};
"
```

### ステップ3-3: シナリオで使用するデータの選定

- 在庫データ、入庫データ等を確認
- どのシナリオでどのデータを使うか決定

### ステップ3-4: ファイルアップロードの確認

シナリオにファイルアップロードが含まれる場合:
- ユーザーからファイルを受け取っていなければ**必ず要求する**
- ファイルの文字コード・フォーマットを確認
- **受け取ったファイルを`outputs/`に保存する**（お客さんへの納品物として同梱）

## フェーズ4: 画面キャプチャ撮影

### ステップ4-1: 環境準備

1. `.env`からポート番号を取得（NEXT_PORT, UVICORN_PORT）
2. フロントエンド/バックエンドサーバーの起動確認
3. Playwrightでログイン

**認証情報:** CLAUDE.md参照

### ステップ4-2: 吹き出しルール

**枠線は使用しない。吹き出しのみ。**

| 色 | 用途 | カラーコード |
|----|------|-------------|
| 赤 | アクション（クリック、入力） | `#dc2626` |
| 緑 | 確認完了、成功状態 | `#16a34a` |
| 青 | 情報、補足説明 | `#2563eb` |

**吹き出しコード:** `templates/tooltip-snippet.js` を参照し、`browser_evaluate`で実行

### ステップ4-3: キャプチャ撮影のポイント

- **画面遷移の方法を必ず示す**: サイドバーのどこをクリックするか等
- 1画面につきキャプチャは**1〜2枚**に抑える（分けすぎない）
- 重要な操作箇所に吹き出しを付ける

**ファイル名規則:** `{番号2桁}-{画面名}.png`

### ステップ4-4: PDF画面の制限事項

**PDF出力画面はスクリーンショットのみ撮影可能**（PDFファイルの直接ダウンロードは不可）

### ステップ4-5: キャプチャのコピー

Playwrightで撮影したスクリーンショットを`images/`にコピー:
```bash
cp .playwright-mcp/.tmp/how-to/{荷主コード}_{シナリオ名}/*.png .tmp/how-to/{荷主コード}_{シナリオ名}/images/
```

## フェーズ5: 完成・確認

### ステップ5-1: HTMLファイル保存

```
保存先: .tmp/how-to/{荷主コード}_{シナリオ名}/{YYYYMMDD_HHMMSS}.html
```

### ステップ5-2: ブラウザで表示（必須）

```bash
open .tmp/how-to/{荷主コード}_{シナリオ名}/{ファイル名}.html
```

## ディレクトリ構成

```
.tmp/how-to/{荷主コード}_{シナリオ名}/
├── {YYYYMMDD_HHMMSS}.html    # 手順書HTML
├── images/                    # スクリーンショット
│   ├── 01-login.png
│   ├── 02-画面名.png
│   └── ...
└── outputs/                   # 納品物（入力/出力ファイル）
    ├── サンプル入力.csv
    └── ...
```
