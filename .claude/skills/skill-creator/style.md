# スキル向けファイルの文体ルール

`.claude/skills/<name>/SKILL.md` に適用する文体ルール。
構造は sample.md / template.md が現物として示す。

## 命令形

- 指示文はすべて命令形で書け
- 終止形（〜する）で書くな。命令形（〜しろ、〜せよ）で書け
- 丁寧語（〜してください、〜しましょう）は使うな

| 禁止 | 命令形 |
|------|--------|
| 〜する | 〜しろ |
| 〜しない | 〜するな |
| 〜すること | 〜しろ |
| 〜してください | 〜しろ |
| 〜であること | 〜にしろ |

## 簡潔性

長文はスキップされ、読まれない。短く読み切れる粒度に保て。

- 1 文は短く、明確に書け
- 1 文 1 要点。複数の要点を 1 文に詰め込むな
- 冗長な説明・前置き・補足は書くな
- 複雑な内容は分割しろ

## フォーマット

書き手と読み手の解釈ズレを防ぐ。視覚で構造が分かる形にしろ。

- 箇条書きを優先しろ。長文の段落で書くな
- 各項目は独立して理解可能にしろ
- ネストで詳細を補足しろ
- ネストで粒度を合わせろ
- 関連項目はグループ化し、階層構造で整理しろ

## 事実性

ハルシネーションを排除する。事実以外を書くな。

- 書ける情報源は 3 つのみ: (a) ユーザー発言 (b) 実在するコード／ファイル (c) 公式ドキュメント
- 推測・推察・想像で書くな
- 不明な点はユーザーに質問しろ。想像で埋めるな

## 例外

- コードブロック内のコメントは命令形ルールの対象外
  - 理由: コード内コメントは説明調が標準。`# Initialize cache` を「キャッシュを初期化しろ」と書き換えると不自然

## ハルシネーションの言い訳を許すな

事実性ルールを破る時、Claude は無自覚に「親切」「整合性」を理由に推測を書く。
以下の思考が浮かんだら、それは間違い。

| 言い訳 | 現実 |
|---|---|
| 「親切のために補足しよう」 | 親切心は事実より優先するな。ユーザーが求めたものだけ書け |
| 「整合性のために補完しよう」 | 補完は推測。書くな。質問しろ |
| 「たぶんこの API 名で合ってる」 | たぶんは禁止。grep / WebSearch で裏取りしろ |
| 「文脈から推察するに〇〇」 | 推察は推測。事実ではない |
| 「一般的にはこうだから」 | 業界一般 ≠ このプロジェクト。コードを読め |
| 「ユーザーは多分こう思ってるはず」 | 思っていない。ユーザーが言ったことだけ書け |
| 「無いと不自然だから書き足す」 | 不自然なら質問しろ。書くな |
| 「だいたい合ってるから大丈夫」 | だいたい = ハルシネーションの種。事実のみ書け |
