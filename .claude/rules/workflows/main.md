# メインワークフロー

## Taskツールでタスク管理

### 必須実行タイミング

- 新しい依頼時
- タスク完了時
- ユーザーからの追加依頼時

### 反映ルール

- 既に実施済みのタスクは追加不要
- 技術的に実施不要と判断したタスクは追加不要
- Taskリストを更新しない場合は理由を明確に説明

### 重要原則

- やるべきことは必ずTaskCreateで記載（忘れることは約束を破ること）
- ユーザーからの依頼・追加依頼は即Taskリストに反映
- 追加コメント受信時: まず返答→優先順位再評価（無視は許されない）
- 1タスクごとにCLAUDE.md確認
- 速さより確実性を優先
- タスクの実行順序はClaude Codeが決定（判断理由を明確に説明）

## 作業開始時

### ブランチ確認

- developからfeatureブランチ作成
- 既存featureならdevelopとの差分確認

### 調査・TDD

- dateコマンドで現在日時確認
- WebSearchで最新情報調査
- テスト先行作成
- 既存コードパターン踏襲

## 作業完了時の必須アクション

### PR作成とブラウザオープン

**featureブランチで作業が完了した場合、必ず以下を実行**:

1. **判断基準を確認**:
   - `git status`で未コミット変更がない（全てコミット済み）
   - `git diff develop...HEAD`でdevelopとの差分が存在
   - **Taskリストの全タスクが完了状態（または空）**

2. **PRを作成する**:
   - 上記の判断基準を全て満たす場合、PRを作成する

3. **PR作成後、必ずブラウザで開く**:
   - `gh pr view --web`を実行
   - レビュー可能な状態にする

### 実行タイミング

- ユーザーから「PR作成」「push」などの言及があった時
- Taskリストの全タスクが完了した時
- 作業が完了し、次のアクションを求められた時

### 注意事項

- ブラウザオープンを忘れることは許されない
- developブランチからのPR作成は厳禁

## テスト作成時

### Frontend

- テスト必須: lib/, hooks/
- テスト不要: UI層, components/shadcn/, 描写テスト

### Backend

- テスト必須: `endpoints/`, `services/`, `utils/`
- テスト不要: `alembic/versions/`
